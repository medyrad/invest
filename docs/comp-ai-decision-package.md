### PC-D02-02 — سهمیه، هم‌زمانی و خطا

- گزینه‌ها: الف) مهمان۳، حساب۲۰ پاسخ کامل در روز UTC؛ ب) مهمان۱، حساب۱۰ برای پایلوت محدودتر. **مصوب: گزینه الف** برای امکان اصلاح برداشت؛ شمارش UTC در UI با موعد reset تهران نشان داده شود. مهمان با principal ناشناس امضاشده سرور؛ پاک‌کردن cookie هویت انسانی یکتا اثبات نمی‌کند. سقف پول سراسری و rate limit مستقل مانع بی‌نهایت‌شدن هزینه باشند.
- هم‌زمانی مصوب: حداکثر۲ نوبت فعال برای هر principal، مهمان یا حساب؛ پیش از اولین تماس، رزرو اتمیک سهمیه/بودجه/slot. نوبت یعنی یک ارسال مشتری تا پاسخ کامل معتبر؛ سؤال روشن‌ساز تولیدشده با مدل هم یک پاسخ است، validation محلی بدون تماس نیست. پاسخ کامل یک debit؛ retry همان کلید duplicate مصرف نمی‌سازد. خطا/refusal نامرتبط/نیمه‌کاره سهمیه پاسخ را آزاد کند، ولی هزینه provider آزاد نمی‌شود مگر تسویه معتبر.
- جلوگیری از retry بی‌پایان: حداکثر۱۰ شروع provider در ساعت برای مهمان و۶۰ برای حساب، شامل خطاها؛ ادمین مقادیر را نسخه‌دار کند، سقف بودجه را دور نزند. هنگام ورود، مصرف موفق و رزرو مهمان همین مرورگر همان روز یک‌بار به حساب افزوده شود؛ عبور از۲۰ ناشی از ادغام تماس تازه مجاز نسازد. خروج/حساب دوم گفتگو یا سهمیه خصوصی را به دیگری منتقل نکند.
- اثر مشتری/هزینه: خطای سرویس سهمیه پاسخ را نمی‌بلعد؛ سوءاستفاده هنوز هزینه واقعی دارد و محدود می‌شود. آزمون مرز روز، login race، دو تب/دو حساب، کلید یکسان با payload متفاوت، شکست تسویه و تغییر policy وسط درخواست روی PostgreSQL؛ هیچ تماس بدون رزرو و هیچ سومین نوبت مجاز نباشد. **اعداد و قواعد این بند مصوب‌اند؛ آزمون هنوز اجرا نشده است.**

### PC-D02-03 — سقف هزینه و token

- گزینه‌ها: الف) سقف سخت۱۰۰دلار در ماه UTC و۰٫۱۰دلار برای یک نوبت؛ ب) پایلوت۲۵دلار/ماه با همان سقف هر نوبت. **مصوب: گزینه الف** با هشدار۸۰٪ و توقف رزرو تازه در۱۰۰٪؛ این بودجه هزینه API است، نه کل هزینه محصول یا SLA. سقف در ادمین نسخه‌دار/ممیزی‌پذیر؛ مدل حق تغییر آن ندارد.
- بودجه مصوب هر نوبت: مجموع تمام فراخوانی‌ها و retry حداکثر۸۰۰۰ input و۱۰۰۰ output token، شامل history، prompt، payload ابزار و reasoning صورتحساب‌شده؛ نه سهم جداگانه برای هر call. حداکثر۴ call مدل، شامل retry، برای محدودکردن حلقه ابزار. قبل هر call با باقیمانده token/پول اجازه صادر شود؛ تجاوز→پاسخ ناقص صریح و مسیر دستی، نه حذف خاموش شرط. خروجی هزار token برای مدل reasoning ریسک قابل سنجش است و افزایش آن نیازمند تصویب تغییر سیاست است.
- مثال محاسبه، نه مصرف اندازه‌گیری‌شده: Sol با۸k ورودی عادی و۱k خروجی، `8000×2/1e6 + 1000×10/1e6 = $0.026`؛ با نرخ بالاتر نوشتن cache۳۰دقیقه روی همه ورودی، `$0.030`. تخفیف cache فرض نشود؛ حالت/قیمت واقعی و هزینه همه تلاش‌ها حساب شوند. رزرو محافظه‌کارانه۰٫۱۰ پیش از نوبت، تسویه هزینه واقعی و آزادسازی باقیمانده؛ هزینه نامعلوم پس از timeout همچنان held تا reconciliation، نه صفر فرضی. در سقف کامل۰٫۱۰، بودجه۱۰۰دلار حداکثر۱۰۰۰نوبت می‌دهد؛ این مثال تضمین ظرفیت یا تعداد پاسخ نیست.
- آزمون لازم: race آخرین اعتبار، rollover ماه، cache/reasoning، retry و usage نامعلوم، قطع ادمین و تغییر نرخ؛ `spent + held ≤ cap` و بدون تماس بی‌بودجه. دو زیرسقف smoke۵دلار و eval۱۵دلار از همان۱۰۰دلارند، نه بودجه اضافه. **همه سقف‌ها و روش رزرو مصوب‌اند.** ارزیابی Sol و مقایسه الزامی Luna مشترکاً در زیرسقف۱۵دلار eval و سقف۱۰۰دلار ماهانه قرار می‌گیرند؛ کمبود بودجه «ناتمام» است، نه مجوز افزایش خودکار یا حذف مقایسه.
