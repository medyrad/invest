**مرز حفاظت و قفل‌ها:** خروجی streaming نیست؛ بایت کامل داخل تراکنش ساخته و سپس پاسخ شبکه ارسال می‌شود. بایت قبلاً تحویل‌شده قابل پس‌گرفتن معرفی نمی‌شود. نویسندگان موجود parent→organization→file دارند؛ خواننده گزارش organization→فایل‌های مرتب‌شده می‌گیرد و پس از آن parent را قفل نمی‌کند. Report ثابت است و قفل نوشتن آن لازم نیست. اسکن و تماس شبکه داخل بخش قفل‌شده نیستند؛ سهمیه/حدود موجود فایل تغییر نکرده‌اند. انتظار قفل محلی۵ثانیه است؛ فقط SQLSTATE `55P03` پس از rollback به۴۰۹ قابل‌فهم تبدیل می‌شود؛ سایر خطاهای سرور به۴۰۰/۴۰۹ پنهان نمی‌شوند. تست مکمل واقعاً `pg_blocking_pids` را در دو connection مشاهده می‌کند؛ تمام‌شدن timeout شاهد موفقیت نیست.

**آزمون و حفظ شواهد:** سه رقابت تاریخی ابتدا همگی شکست خوردند و پس از اصلاح، بدون تغییر فایل یا assertion همگی موفق شدند. مجموعه مرتبط نهایی **۸۴ موفق،۵۲ نامرتبط کنارگذاشته** است:۷۴ بررسی موجود و۱۰ مکمل. با سه مستقل، **۸۷ pytest یکتای موفق**؛ اجرای میانی/هدفمند دوباره جمع نشده است. **۴ تست Playwright هدفمند موفق** و دو probe مستقل با خروجی تازه موفق‌اند. probeها فقط به مقصد شواهد تازه هدایت شدند؛ assertion تاریخی تغییر نکرد. بخش HTML موبایل probe همان نمونه تاریخی ثبت‌شده را می‌خواند و دانلود تازه معرفی نمی‌شود. خطاهای آماده‌سازی اولیه config و دو ایراد fixture تست تازه در log محلی محفوظ‌اند؛ آن‌ها شکست محصول نهایی یا قبولی مستقل شمرده نشده‌اند.

Ruff فایل‌های Python متأثر، ESLint فایل‌های TS/TSX متأثر و TypeScript موفق شدند؛ build نهایی backend/web موفق است. ۱۸۰۱قاعده بدون تغییر،۹سفر کامل و OTP دوباره اجرا نشدند. regression محدود فایل/دانلود، رضایت و جانشینی، پرونده و حفظ تاریخچه در۸۴تست هست. migration تازه لازم نشد و DB فعال reset/rollback/migrate نشد. [حفظ۱۲۶۲ردیف قبلی در۱۵مدل، env و تطبیق۱۰۸فایل backend فعال](fix-01-evidence/preservation.json) موفق است؛ هیچ گزارش/آزمون مستقل تاریخی تغییر نکرده است.

**تعیین تکلیف image:** تفاوت image تاریخی گزارش تحویل با بررسی تستر واقعی است؛ علت آن با شواهد موجود قابل اثبات نیست. fingerprint/endpoint یکسان، برابری باینری تاریخی را ثابت نمی‌کند. در این مأموریت یک build نهایی از همین کد و Dockerfile/lockهای موجود مشاهده و ثبت شد؛ image ساخته‌شده با container فعال backend و web تطبیق داده شد. workspace-jobs همان image backend را دارد؛ scanner موجود، جدا از این build و بدون تغییر، با شناسه واقعی خودش ثبت شده است. source backend فعال با۱۰۸فایل workspace برابر است؛ BUILD_ID و hash تجمیعی۴۱۵فایل bundle وب نیز در manifest آمده‌اند. این زنجیره منشأ اجرای فعلی است؛ ادعای بازسازی باینری یکسانِ نسخه تاریخی نیست.

**تفاوت طراحی و محدودیت:** فرم‌های بومی و پیشرفت تازه، چندانتخابی۲۲خدمت زمین به‌جای picker و ارتفاع بیشتر، کارت خانواده بین‌المللی، کنترل D29، فضای D30 و فایل D32 همچنان با تصویر مرجع یکسان معرفی نمی‌شوند؛ اختلاف‌های گزارش مستقل محفوظ‌اند و ثبتشان تأیید انسانی نیست. این بسته فقط چهار نقص مشخص UI را اصلاح کرده؛ طراحی تازه یا حذف قابلیت ندارد. نمونه‌های نهاد/فراخوان تاریخی‌اند، وعده پوشش یا اعتبار فعلی نیستند. پذیرش مستقل بسته، تأیید انسانی طراحی، داوری خبره D28 و عرضه بازند؛ S09/F40 یا انتشار عمومی آغاز نشده است.
