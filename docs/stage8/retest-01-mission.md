## نسخه و بررسی ضروری

ابتدا hash کد، image کانتینرهای فعال3108، BUILD_ID و hash bundle وب را با fix-01-evidence/manifest.json تطبیق بده. از image و ابزار سالم موجود استفاده کن. علت اختلاف image تاریخی نامعلوم مانده؛ تأیید نسخه تازه به معنی اثبات برابری تاریخی نیست. commit مستندات جدید اختلاف کد محصول محسوب نمی‌شود.

۱. S08-IT-001: دو بازتولید تاریخی HTTP دانلود HTML/ZIP در independent-tests/test_download_race.py را دست‌نخورده اجرا کن. هر دو ترتیب جانشینی/دانلود را با connection واقعی و رخداد کنترل‌شده بسنج: جانشینی زودتر باید اختیار قبلی را رد کند؛ دانلود زودتر باید تا پایان ساخت بایت ترتیب تراکنشی معتبر داشته باشد. مسیر JSON گزارش core و فایل مرتبط نیز چون تغییر کرده‌اند regression محدود داشته باشند. pg_blocking_pids یا شاهد هم‌ارز نشان دهد انتظار واقعی قفل است؛ timeout یا نخ ناتمام موفقیت محسوب نشود.

۳. S08-IT-003: زمین۳۶۰/۳۹۰ را واقعاً ببین؛ متن پیشرفت خوانا، بدون ستون تک‌واژه‌ای و تداخل دکمه، focus/Tab برقرار. صرف نبود overflow کافی نیست.

۴. S08-IT-004: دو گروه «محدوده، حقوق و مشوق‌های قابل بررسی» و «ساکنان و اسکان موقت» با فیلدهای متعلق، ترتیب و شرط مرجع در۱۴۴۰/۳۹۰ حفظ شده باشند؛ عنوان تزئینی بدون ساختار قبول نیست. تغییر شرط و بازگشت، داده مؤثر/خام را درست نگه دارد.

## دامنه آزمون و سرعت

سه رقابت تاریخی و مجموعه مرتبط۸۴تایی گزارش‌شده یک‌بار اجرا شوند؛ استقلال انتظارهای مکمل را بررسی کن و فقط برای شکاف واقعی آزمون تازه اضافه کن. چهار تست مرورگر اصلاح و دو probe با مقصد خروجی تازه اجرا شوند؛ شواهد تاریخی بازنویسی نشوند. نمونه‌های UI را واقعاً با مرجع/قبل مقابله کن؛ آزمون DOM به‌تنهایی تأیید طراحی نیست.

۱۸۰۱قاعده نامتأثر،۹سفر کامل و suite احراز دوباره اجرا نشوند مگر تغییر/شکست/ریسک تازه دلیل مشخص ایجاد کند. runnerهای DB مشترک ترتیبی باشند. بازاجرای زیرمجموعه شمار یکتا را زیاد نمی‌کند. نیاز به rebuild فقط در صورت ناسازگاری واقعی محیط است؛ اختلاف نسخه حل‌نشده را پنهان نکن. زمان آماده‌سازی، build در صورت نیاز، تست و گزارش جدا ثبت شود.

گزارش مستقل قبلی پوشش اصلی۹خدمت و۷۸پیکربندی را دارد؛ برای نتیجه تجمیعی به شواهد تاریخی معتبر ارجاع بده، اجرای تازه ادعا نکن. همه یافته‌های مستقل را جمع کن و با نخستین شکست متوقف نشو. محصول، env، وضعیت پذیرش و شواهد تاریخی را تغییر نده؛ DB فعال reset/rollback نشود. داده UI فقط مصنوعی باشد.
