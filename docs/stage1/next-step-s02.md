# قدم بعد پیشنهادی: S02 — زیرساخت قابل اجرا

وضعیت: پیشنهاد برای دستور بعدی کاربر؛ این مرحله هنوز شروع یا برای پیاده‌سازی مجاز نشده است. چهار سیاست B01–B04 در D25–D29 بسته‌اند. نتیجه تحلیل جاری در [گزارش تحلیل](clarification-analysis.md) است؛ گیت اجرای کل محصول همچنان باز است.

## دامنه همین قدم

۱. در feature مستقل `specs/004-platform-foundation/` مشخصات زیرساخت، معیار پذیرش، قراردادهای مشترک و plan/tasks/checklist تهیه و با analyze بررسی شوند. شماره feature با شماره مرحله متفاوت است؛ مسیرهای 002/003 در baseline برای خدمات تخصصی و دستیار پیش‌بینی شده‌اند. ابتدا نسخه‌های سازگار و پشتیبانی‌شده Python/Node/Django/DRF/Next/React/PostgreSQL از منابع رسمی بررسی و قفل شوند؛ نسخه‌های پیشنهادی فعلی، lock نهایی نیستند.

۲. پس از رفع یافته‌های مسدودکننده همان feature و در دامنه دستور اجرای S02، اسکلت بک‌اند و فرانت‌اند، تنظیم محیط development/test/public، PostgreSQL محلی و Docker، مدل پایه حساب و migration اولیه ایجاد شوند. AUTH_USER_MODEL و مدل پایه حساب پیش از migration وابسته تثبیت شوند؛ منطق OTP و نشستِ سفر ورود در S03 تکمیل می‌شود. فرانت پایه فارسی/RTL و مسیر ارتباط با API را فراهم کند؛ پذیرش طراحی صفحات محصول متعلق به S04 و مرجع سرمایه‌گزین است.

۳. قرارداد خطا/شناسه درخواست، مبدأ API و CSRF، سلامت سرویس/دیتابیس، اصول version/idempotency و OpenAPI پایه در حد همین مرحله مشخص و آزموده شوند. fixture حساب و تست DB روی PostgreSQL مقصد باشد. CI، dependency lock و دستور نصب/اجرای تمیز مستند شوند. اتصال واقعی AI/SMS، فایل مشتری و داده واقعی به گیت‌های خودشان تعلق دارند.

## خروجی قابل بررسی

| خروجی | شاهد پذیرش |
|---|---|
| spec/plan/tasks/checklist و قرارداد پایه مستقل | analyze بدون یافتهٔ مسدودکننده برای دامنه S02؛ وضعیت گیت‌های باقی محصول حفظ شود |
| backend/frontend و PostgreSQL قابل اجرا | نصب از محیط تمیز با lock، اجرای سرویس‌ها و تست سلامت با DB موجود/ناموجود |
| مدل پایه حساب و migration | ساخت DB خالی و اجرای migration، fixture مستقل دو حساب و عدم وابستگی به SQLite |
| جدایی محیط و تنظیمات | `.env.example` بدون secret، خطای روشن برای تنظیم ضروری مفقود، عدم فعال‌شدن تنظیم آزمایشی در حالت public |
| داده پایدار و CI | ماندن داده آزمایشی پس از restart بدون حذف volume، اجرای checks در همان محیط وابستگی، ثبت فرمان/نسخه/نتیجه |
| پایان مرحله | گزارش محدودیت‌ها و قدم بعد S03؛ هیچ موفقیت mock یا scaffold به‌عنوان محصول کامل معرفی نشود |

تسک‌های مرجع: T003–T008؛ در feature زیرساخت به کارهای کوچک‌تر و قابل آزمون شکسته می‌شوند. T001 نگاشت تدریجی منبع را برای قابلیت‌های مقصد دنبال می‌کند و مانع مصنوعی ساخت اسکلت بدون فرم بیزینسی نیست. اجازه S02 به اجرای خودکار تمام ۷۲ تسک باز یا عرضه عمومی تعمیم ندارد.

B08 و نگاشت فیلدها پیش از پذیرش UI/فرم S04؛ سیاست فایل B07 در T024 پیش از فایل S05؛ ارزیابی نمونه‌های تطبیق در T030 پیش از پذیرش S06؛ اعلان B06 در T020 پیش از S07؛ schema هر خدمت پیش از S08؛ مدل/هزینه/سهمیه/نگهداری AI در T062 پیش از S09؛ اتصال بیرونی B06 در T069؛ ظرفیت، بازیابی، تیم پاسخ‌گو و SMS واقعی پیش از عرضه S11. تعیین تکلیف حذف/تعویق دامنه، داده نمونه و قیمت‌گذاری B06 با کاربر ثبت می‌شود و از پذیرش زیرساخت نتیجه گرفته نمی‌شود.
