## ایرادها و اولویت اصلاح

### CORE-IT-003 — زیاد / اولویت۱ — دورهٔ کار بهره‌برداری قابل ثبت نیست

اثر: قابلیت F09 آماده اعلام شده ولی مالک در مسیر operator نمی‌تواند دورهٔ کار نوع‌دار ثبت کند؛ داده لازم این مسیر در فرم/قرارداد فعال وجود ندارد. معیار: پذیرش رجیستری F09 «مسیر بدون الزام بودجه سرمایه‌گذار و با شرح خدمت و دوره کار کند» و D29 واحد مدت صریح.

بازتولید روی schema هدف: `active_keys(['operator'],False,{})` را بگیرید و فیلدهای فعال با unit در DAY/MONTH/YEAR را بررسی کنید؛ **فهرست خالی است**. مسیر operator در routes وجود دارد، ولی duration فقط investor/lessee/heritage و execution برای participation/contractor فعال می‌شوند. انتظار: کنترل و قرارداد دورهٔ کار متناسب با منبع در مسیر فعال؛ واقعیت: هیچ Quantity زمانی فعال نیست. [assertion مستقل](independent-evidence/operator.txt). این بررسی schema واقعی است، نه ادعای اجرای کامل سفر تازه operator در UI.

پیشنهاد بازگشت: fixture مالک operator با دوره و مبنای شروع، UI قابل ورود، round-trip و تغییر/بازگشت مسیر؛ دوره با بازگشت سرمایه یا افق IRR ادغام نشود. نام فیلد/واحد تازه بدون قرارداد محصول توسط تستر اختراع نشده است.

### CORE-IT-001 — متوسط / اولویت۲ — ورودی بدشکل جست‌وجو HTTP500 می‌دهد

اثر: مصرف‌کننده به‌جای خطای قابل اصلاح معیار، خطای داخلی می‌گیرد. معیار: خطای کنترل‌شده قرارداد HTTP/US3؛ ورودی JSON نامعتبر نباید استثنای داخلی بسازد.

بازتولید مهمان: GET `/api/v1/core/opportunities` با query `criteria={"important":[{}]}` یا `{"important":[[]]}`. انتظار۴۰۰ با envelope؛ واقعیت هر دو۵۰۰ و TypeError ناشی از عضویت مقدار unhashable در WEIGHTS. دو ورودی هم‌نوعِ عدد/bool کنترل‌شده۴۰۰ می‌دهند. روی image آزمون و endpoint فعال هر دو بازتولید شد. [آزمون](independent-evidence/isolated-recovery.txt)، [probe فعال](independent-evidence/http-malformed.json). پیشنهاد بازگشت: انواع عضو important قبل از lookup اعتبارسنجی و عدم نوشتن/۵۰۰ بررسی شود؛ خطای عمومی سرور بلعیده نشود.

### CORE-IT-002 — متوسط / اولویت۲ — ساختار گروه‌بندی مقایسه مرجع حذف شده
