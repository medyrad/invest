# تجربه محلی هسته سرمایه‌گزین

محیط فقط برای داده و حساب مصنوعی است؛ پیامک، احراز واقعی، تضمین سود یا عرضه عمومی نیست.

1. از ریشه پروژه `python3 scripts/dev_runtime.py up --build` را بار اول و `python3 scripts/dev_runtime.py up` را دفعات بعد اجرا کنید. [خانه با 127.0.0.1](http://127.0.0.1:3108/)، [خانه با localhost](http://localhost:3108/) و [انتخاب نقش مصنوعی](http://127.0.0.1:3108/local-roles) به همان runtime اصلی development می‌رسند. پنج نقش آماده‌اند: مالک، ادمین مستقل، مشتری و دو کارشناس. هیچ رمز، OTP یا token در این راهنما لازم نیست؛ ابزار نقش فقط development/test کار می‌کند.
2. برای تجربه هم‌زمان از پروفایل‌های مستقل مرورگر یا مرورگرهای جدا استفاده کنید. چند تب یا چند پنجره ناشناس Chrome لزوماً cookie مستقل ندارند. روش ساده‌تر، تکمیل و ذخیره هر اقدام و سپس عوض‌کردن نقش از صفحه نقش‌ها در همان مرورگر است.
3. مالک: [ثبت فرصت و پیش‌نویس‌ها](http://127.0.0.1:3108/drafts). پروژه، صندوق یا فروش و مالک فردی/سازمان مصنوعی دارای اختیار را انتخاب کنید. فیلدهای شرطی و مقدار دقیق را وارد، صریح ذخیره و نسخه ذخیره‌شده را برای بررسی ارسال کنید. «نامعلوم» عدد صفر نیست. کد/واحد یا مبنای ناسازگار رد می‌شود. پیش از تغییر نقش، ورودی را ذخیره کنید.
4. ادمین مستقل: [پنل بررسی](http://127.0.0.1:3108/admin). در نمایندگی مدارک، منبع مستقل، نتیجه و دلیل را بررسی کنید. فرصت ارسال‌شده، اختلاف با نسخه عمومی و تاریخچه را باز کنید؛ اصلاح/رد/تأیید مستقل ثبت کنید. مشتق تصویر فقط با انتخاب صریح و مدرک تضمین فقط با بررسی مستقل قابل احراز است؛ مدرک خصوصی عمومی نمی‌شود. توقف/بازنشر مستقل از revision است.
5. مهمان یا مشتری: [فرصت‌ها](http://127.0.0.1:3108/opportunities). مسیر و ترجیح‌ها را انتخاب کنید؛ هیچ فرصت فعالی صرفاً با امتیاز پایین حذف نمی‌شود. درصد تطبیق، احتمال سود نیست. [مقایسه](http://127.0.0.1:3108/compare)۲تا۴ هم‌نوع، واحد/مبنای ناسازگار را غیرقابل‌مقایسه نشان می‌دهد. منتخب‌ها و شرایط در [حساب](http://127.0.0.1:3108/saved) نگه داشته می‌شوند.
6. در جزئیات فرصت، شرح پیگیری را بنویسید و صریح درخواست کنید. رسید به [درخواست‌ها](http://127.0.0.1:3108/requests) می‌رسد. وجود پرونده فعال مشابه با توضیح روشن، مسیر موجود را پیشنهاد می‌دهد؛ متن جدید پنهانی به آن اضافه نمی‌شود.
7. ادمین به «کارشناس مصنوعی یک» ارجاع دهد. کارشناس از [کارتابل](http://127.0.0.1:3108/expert) پرونده را باز، پاسخ انسانی، گام بعد و موعد پیگیری ثبت کند. مشتری با تازه‌سازی همان پرونده پاسخ و نسخه ثابت فرصت را می‌بیند. پس از پاسخ نهایی، مشتری می‌تواند بستن را تأیید کند؛ رسید خودکار، پاسخ انسانی نیست.
8. گفتگو بدون اشتراک شماره کامل است. رضایت برای کارشناس نام‌دار و صاحب فرصت جداست؛ لغو دسترسی بعدی را قطع می‌کند. بعد از تغییر کارشناس، رضایت تازه لازم است. صاحب فرصت با رضایت تماس، عضو گفتگو نمی‌شود؛ دسترسی تماس او در فضای مالک ظاهر می‌شود. شماره‌ای که قبلاً دیده شده قابل پس‌گرفتن نیست.
9. پیوست پرونده از فضای خصوصی بارگذاری می‌شود؛ تا scanner و parser آن را پاک اعلام نکنند قابل اشتراک نیست. فضای دریافت از زیرساخت پیش‌نویس موجود استفاده می‌کند؛ پیش‌نویس فایل‌ها در حساب قابل مدیریت است. حذف و بازیابی مطابق D30 است و فایل مورد استناد تاریخچه purge نمی‌شود.
10. [پروفایل و اعلان‌ها](http://127.0.0.1:3108/profile) و [کتابخانه](http://127.0.0.1:3108/library) مستقل‌اند. راهنمای هر فرصت از جزئیات قابل دریافت است؛ گزارش با snapshot/فرض/واحد/نسخه ثابت ذخیره می‌شود و دانلود آن پرونده تازه ایجاد نمی‌کند.

اگر نسخه در رقابت تغییر کرد، متن واردشده حفظ است؛ «دریافت آخرین نسخه» را بزنید و دوباره تصمیم بگیرید. بعد از بسته‌شدن، پیگیری مرتبط با اقدام تازه و رسید تازه ساخته می‌شود. توقف فرصت سابقه پرونده را حذف نمی‌کند.

شناسه اجرا: [build وب](http://127.0.0.1:3108/core-version.json) و [نسخه/نوع runtime بک‌اند](http://127.0.0.1:3108/api/v1/core/version). runtime اصلی باید `primary-development` باشد؛ اجرای test/evidence باید نام و پورت خودش را حفظ کند. فرصت‌های دارای برچسب «داده مصنوعی توسعه» از published API و گردش واقعی انتشار آمده‌اند، اما فرصت یا احراز واقعی نیستند. خدمات تخصصی S08 و دستیار متصل S09 هنوز در بسته‌های بعدی‌اند؛ صفحه مقصد وضعیت واقعی را توضیح می‌دهد.

## بازتولید فنی

روی محیط موجود، از ریشه پروژه؛ env موجود و رازها حفظ می‌شوند و port/origin عمومی همگام می‌شوند:

```sh
python3 scripts/dev_runtime.py up
docker compose --env-file .env -f deploy/compose.yaml run --rm --no-deps test /app/.venv/bin/pytest -q
```

برای مرورگر، از frontend و Node موجود پروژه:

```sh
export PATH="/home/mehdirad/Projects/company/invest/.tools/runtimes/node-v24.22.3-linux-x64/bin:$PATH"
CORE_URL=http://127.0.0.1:3108 npx playwright test --config=core.playwright.config.ts
CORE_URL=http://127.0.0.1:3108 npx playwright test --config=core-regression.playwright.config.ts
```

Chrome موجود /usr/bin/google-chrome استفاده می‌شود. مجموعه core با accountهای مصنوعی seed و پنل‌های واقعی اجرا می‌شود؛ داده آزمون خود را برچسب می‌زند. rollback فقط داخل DB ایزوله pytest است. برای تغییر کد، پیش از up، imageهای backend/test/web با compose build ساخته شوند. اجرای محلی روی loopback، انتشار عمومی نیست.
