# برنامه فنی خدمات تخصصی

## زمینه و پژوهش
Django/DRF/PostgreSQL و Next/React موجود؛ نصب/زیرساخت تازه لازم نیست. منبع و شرط‌ها پیش از ساخت در mapping ثبت شده‌اند. خدمات به native form و قواعد Python تبدیل می‌شوند؛ runtime وابسته به HTML engine/DOM/iframe/Node نیست. source فقط مرجع آزمون و طراحی است.

## طراحی
- workspace.Draft و DraftRevision/DraftValue/PrivateFile موجود، مالک فردی/سازمانی و D30/D32 استفاده می‌شوند؛ kind تا نام خدمت گسترش افزایشی دارد. services.schemas تعریف نسخه‌دار هر خدمت و فیلد/شرط دارد؛ قواعد تخصصی تابع‌های بومی مستقل همان ماژول‌اند، نه موتور فرم‌ساز محصول عمومی.
- apps.services ارزیابی، schema، گزارش و snapshot ارسال‌شده را ارائه می‌دهد. کلید/تعارض از الگوی receipt و قفل موجود؛ freeze داده مؤثر و file refs پس از بررسی server.
- Case موجود subject فرصت یا خدمت را با CHECK دقیقاًیکی، FK nullable افزایشی و constraint پرونده فعال خدمات می‌گیرد. ServiceSubmission immutable و به Draft وصل است؛ فرصت صوری ساخته نمی‌شود. consent/assignment/message/jobs/notification از هسته استفاده می‌شوند.
- گزارش core.Report با tag موضوع خدمت ذخیره می‌شود؛ دانلود owner-only و با اختیار جاری است، پرونده نمی‌سازد. پنل پروفایل خروجی خدمت را از گزارش فرصت تشخیص می‌دهد.
- Money/Quantity از catalog و Decimal/رشته و namespace invest.service.<kind با underscore به‌جای خط تیره> استفاده می‌کنند. مبلغ خارجی با currency code/version و Decimal دقیق، بدون base TOMAN/FX گزارش می‌شود؛ ادعای تبدیل ندارد. نرخ بدهی ساده عدد نوع‌دار درصد است، IRR نام‌گذاری نمی‌شود.
- اعتبار سازمان در هر خواندن/نوشتن چک می‌شود؛ برای پرونده خدمت سازمانی، نماینده جاری مشتری مجاز است، actor تاریخی محفوظ می‌ماند و رضایت پس از جانشینی تازه لازم است. داده تماس فرم در DTO عملیاتی پخش نمی‌شود.
- فرانت پوسته Tools/ToolView مرجع، راهنمای کناری، عکس‌ها/گروه‌ها/ترتیب و controls بومی با state حساب و guard پاسخ دیررس؛ guest memory تا ورود محفوظ، هنگام خروج/تعویض حساب پاک. فهرست drafts و profile/library مشترک، مسیرهای stable /tools/<service>.
- F30 تمام۶۱config و۱۷config تکمیلی taxonomy از metadata منبع به conditional questions/guard/actions و راهنمای بومی تبدیل می‌شوند. مسیر investor هسته full common+specific، سایر نقش‌ها بدون تحمیل سؤال آورده سرمایه‌ای به operator/contractor؛ D28 و وزن‌ها عوض نمی‌شوند.

## گیت constitution
مرجع و تصمیم حاکم، حفظ طراحی و اختلاف D26/D29/D32، کنترل server، Decimal/واحد، تاریخچه و حفظ داده، تست PostgreSQL/مرورگر، و عرضه جدا رعایت می‌شوند. مانع اجرایی مشخص باز نیست؛ اعداد retention واقعی/ارز/ضریب اثر تصمیم مصوب فرض نمی‌شوند.

## آزمون و تحویل
قواعد داده‌محور با انتظار منبع، مرز/مقدار/دو حساب/سازمان/نسخه/فایل/snapshot/concurrency؛ migration و حفظ داده قدیمی؛ سفر کامل۹خدمت و شاخه‌های پرخطر و regression محدود هسته. runnerهای DB ترتیبی؛ build هنگام استفاده واقعی. گزارش/manifest/راهنما و commit/push معمول؛ توقف پس از آماده آزمون مستقل جامع، نه پس از تسک.

## تثبیت اجرا
تعریف‌های مقدار در value-fields-v1.json منجمد و migration catalog.0011 افزایشی است؛ فایل منجمد در نسخه‌های آینده تغییر نمی‌کند. ظرفیت غیرنقدی Quantity با ITEM/PERSON/SQUARE_METRE/TONNE/SERVICE_HOUR/SESSION@1 و دوره مستقل است؛ ساعت خدمت یا جلسه به روز/شخص یکتا تبدیل نمی‌شوند. مبنای مدت صریح است. کاتالوگ مکان از همان Province موجود خوانده می‌شود. Source-of-truth احراز، مرجع جاری سازمان و سرور است؛ رخداد بین‌تب یا پروفایل شغلی اختیار ایجاد نمی‌کند.

بسته دارای پیوست، ZIP مجاز با HTML مستقل/manifest/محتوای پاک است؛ پاسخ گزارش HTML بدون پیوست و URL مستقل HTML حفظ شده‌اند. فایل ورودی ZIP پذیرفته نمی‌شود. درگاه صلاحیت و اطلاعات تاریخی فراخوان در خروجی بومی و گزارش دیده می‌شوند. گزینه مکان هر خدمت از معنای همان مرجع می‌آید: proposal استان مشخص، foreign نامعلوم، charity هرجا نیاز تاییدشده بیشتر، land همه استان‌ها؛ کدهای واقعی استان از کاتالوگ مشترک‌اند.
