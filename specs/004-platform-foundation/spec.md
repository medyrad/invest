# Feature Specification: زیرساخت قابل اجرای invest — S02

**Feature Branch**: مستقل از شاخه؛ مسیر `004-platform-foundation`.
**Created**: 2026-11-17
**Status**: S02 پیاده‌سازی و آزموده شد؛ گزارش در docs/stage2/report.md.
**Input**: دستور «برو قدم بعدی» پس از [شرح S02](../../docs/stage1/next-step-s02.md). سیاست‌های D01–D29 پابرجا هستند.

## User Scenarios & Testing

### User Story 1 - راه‌اندازی مستقل و بازتولیدپذیر (Priority: P1)

توسعه‌دهنده محیط خالی را با دستور مستند راه‌اندازی کند؛ نتیجه به سرویس پروژه دیگری وابسته نباشد.
**Why this priority**: پایه همه قابلیت‌های بعدی است.
**Independent Test**: نصب از نسخه‌های قفل‌شده، شروع سرویس، ثبت دو حساب آزمایشی، restart و بازیابی همان داده.
**Acceptance Scenarios**:
1. Given محیط تازه، When دستور نصب اجرا شود، Then سرویس‌های همین پروژه با نسخه ثبت‌شده شروع شوند و پروژه‌های دیگر تغییر نکنند.
2. Given دو حساب مستقل، When داده restart شود، Then شناسه/اطلاعات هر دو حفظ و شماره canonical تکراری رد شود.
3. Given manifest ناسازگار با lock، When نصب ثابت اجرا شود، Then شکست روشن بدهد و نسخه حدسی انتخاب نکند.

### User Story 2 - سلامت و خطای قابل پیگیری (Priority: P1)

مسئول عملیات زنده‌بودن سرویس را از آماده‌بودن داده جدا ببیند و خطا را بدون اطلاعات حساس پیگیری کند.
**Why this priority**: قطعی داده نباید موفق گزارش شود.
**Independent Test**: داده برقرار/قطع/برگشته و خطای مسیر/روش/ورودی بررسی شود.
**Acceptance Scenarios**:
1. Given داده قطع، When سلامت خوانده شود، Then زنده‌بودن موفق و آمادگی ناموفق باشد؛ پس از بازیابی آمادگی موفق شود.
2. Given خطا، When پاسخ برسد، Then کد پایدار، پیام فارسی، fields و شناسه همسان بدنه/سرآیند موجود و secret/traceback/شماره غایب باشد.
3. Given شناسه پیگیری ورودی نامعتبر، When درخواست پردازش شود، Then شناسه امن جدید تولید شود و متن مخرب وارد log/پاسخ نشود.

### User Story 3 - مرز امن ورود آینده و محیط عمومی (Priority: P1)

عملیات تغییردهنده بدون توکن و مبدأ معتبر مرورگر اجرا نشود و تنظیم آزمایشی به محیط عمومی راه پیدا نکند.
**Why this priority**: ورود S03 به این مرز وابسته است.
**Independent Test**: نمونه تغییردهنده ناشناس با/بدون توکن و مبدأ صحیح، و اعتبارسنجی public بدون انتشار.
**Acceptance Scenarios**:
1. Given مهمان، When درخواست بدون توکن یا از مبدأ نامعتبر باشد، Then رد شود؛ کنترل مثبت معتبر موفق باشد و ورود شرط حفاظت نباشد.
2. Given public با secret مفقود/آزمایشی، debug یا کد ورود نمایشی، When شروع شود، Then پیش از پذیرش درخواست شکست بدون افشای secret رخ دهد.
3. Given حساب بدون رمز، When احراز واقعی انجام نشده، Then مالکیت شماره یا ورود موفق ادعا نشود؛ مسیر ورود/OTP این مرحله وجود ندارد.

### User Story 4 - پایه فارسی و کنترل کیفیت (Priority: P2)

تیم محصول پوسته پایه فارسی با ارتباط هم‌مبدأ داشته باشد و تغییر ناسازگار پیش از ادغام دیده شود.
**Why this priority**: حفظ هویت مرجع و یکسانی محیط تحویل.
**Independent Test**: مرورگر روی خروجی ساخته‌شده زبان/جهت/فونت و مسیر هم‌مبدأ را بررسی کند.
**Acceptance Scenarios**:
1. Given موبایل/دسکتاپ، When پوسته باز شود، Then فارسی/RTL و فونت محلی مرجع بارگذاری شوند؛ این پوسته ادعای تکمیل صفحات محصول ندارد.
2. Given مسیر هم‌مبدأ، When روش/بدنه/پرس‌وجو/کوکی/توکن ارسال شوند، Then بدون تغییر معنایی یا redirect ناخواسته پاسخ/کوکی برگردند.
3. Given اجرای خودکار کنترل‌ها، When تست قرارداد/مجوز/ساخت/migration شکست بخورد، Then نتیجه ناموفق و شاهد بازتولیدپذیر ثبت شود.

### Edge Cases

- پورت اشغال/داده پروژه دیگر: محیط ایزوله و توقف فقط سرویس خود؛ حذف volume دیگر ممنوع.
- داده قطع/credential نامعتبر: مهلت محدود و آمادگی ناموفق بدون جزئیات اتصال.
- شماره نامعتبر/تکراری: قید canonical و یکتایی؛ ایجاد حساب تأیید شماره نیست.
- خطای قبل/بعد احراز: شکل یکنواخت و شناسه، نه صفحه debug.
- تغییر مقصد build/runtime یا slash: قرارداد و تست خروجی production رفتار را تعیین کند.
- public بدون host/HTTPS/secret مناسب یا با OTP آزمایشی: شکست آغاز؛ public به‌تنهایی اجازه عرضه نیست.

## Requirements

### Functional Requirements

- **FR-001**: محیط و داده آزمایشی مستقل و قابل ساخت از محیط خالی با نسخه قفل‌شده، بدون تغییر پروژه دیگر باشد.
- **FR-002**: داده پس از restart حفظ و migration روی پایگاه خالی قابل تکرار باشد.
- **FR-003**: حساب پایه از نخستین migration با شناسه مستقل، شماره canonical یکتا، زمان ایجاد/تغییر و وضعیت فعال/احرازنشده وجود داشته باشد؛ نقش/ورود خودکار ندهد.
- **FR-004**: زنده‌بودن مستقل از داده؛ آمادگی با اتصال واقعی حساب برنامه و انتظار محدود؛ قطعی موفق گزارش نشود.
- **FR-005**: خطا کد پایدار، پیام فارسی، fields و شناسه داشته و داده حساس/traceback افشا نکند.
- **FR-006**: همه پاسخ‌ها شناسه امن پیگیری داشته و خطا همان شناسه را در بدنه/سرآیند حمل کند.
- **FR-007**: حفاظت درخواست تغییردهنده برای مهمان و واردشده آزموده شود؛ فقط مبدأ و توکن معتبر مجاز باشند.
- **FR-008**: محیط development/test/public جدا و public با تنظیم خطرناک fail-closed باشد؛ ورود/OTP عملیاتی هنوز ساخته نشود.
- **FR-009**: مرورگر API هم‌مبدأ مصرف کند و method/body/query/status/cookie بدون تغییر معنایی منتقل شوند.
- **FR-010**: پوسته فارسی/RTL با فونت محلی و هویت اصلی؛ طراحی و سفرهای محصول به S04/مراحل وابسته تعلق دارند.
- **FR-011**: قرارداد پایه خطا/CSRF/health و قواعد version/idempotency قابل آزمون مشخص شوند؛ عملیات دامنه این مرحله اجرا نشوند.
- **FR-012**: کنترل نصب ثابت، کیفیت کد، migration، قرارداد/مجوز و مرورگر روی خروجی ساخته‌شده وجود داشته و شکست پنهان نشود.
- **FR-013**: راه‌اندازی/تست/توقف امن و شاهد نسخه/فرمان/نتیجه/محدودیت ثبت شود؛ S02 محصول کامل معرفی نشود.

### Key Entities

- حساب پایه: هویت و شماره یکتا، فعال/غیرفعال، احرازنشده؛ نقش محصولی قابل تنظیم از کلاینت ندارد.
- تنظیم محیط: اتصال/امنیت و جدایی آزمایش/عمومی؛ secret خارج مخزن.
- نتیجه سلامت/خطا: وضعیت و شناسه، فاقد اطلاعات خصوصی.
- شاهد اجرا: نسخه، قرارداد/تست، نتیجه و محدودیت، فاقد credential.

## Success Criteria

### Measurable Outcomes

- **SC-001**: نصب ثابت و راه‌اندازی محیط تازه یک بار کامل موفق و قابل بازاجرا، بدون مداخله در پروژه دیگر باشد.
- **SC-002**: دو حساب بعد restart با همان شناسه بازیابی؛ نمونه نامعتبر و تکراری رد شوند.
- **SC-003**: داده برقرار/قطع/برگشته و خطاهای تعریف‌شده همگی نتیجه مورد انتظار و شناسه بدون افشا داشته باشند.
- **SC-004**: همه سناریوهای توکن/مبدأ نامعتبر و تنظیم public خطرناک رد و کنترل مثبت موفق باشد.
- **SC-005**: پوسته در عرض ۳۹۰ و ۱۴۴۰ و ارتباط هم‌مبدأ روی خروجی تحویل آزموده شود.
- **SC-006**: هر نیازمندی تسک و شاهد پذیرش داشته باشد؛ شکست باقی مانع تکمیل همان دامنه شود.

## Assumptions

- دستور فعلی مشخصات، اجرا و آزمون S02 را مجاز می‌کند؛ S03 و انتشار دستور بعدی می‌خواهند.
- بازیگر این feature تیم توسعه/عملیات است؛ بار مشتری و SLA در B07 باقی‌اند.
- داده فقط ساختگی است؛ شماره دارای قالب معتبر، مالکیت اثبات‌شده نیست.
- public صرفاً تنظیم/تست دارد؛ میزبان/TLS واقعی/پیامک/AI هنوز گیت‌های بعدی‌اند.
- قواعد مالی/فرصت/پرونده D25–D29 تغییر یا اجرا نمی‌شوند.
