# پژوهش فنی A1 — بررسی فایل و اجرای job

تاریخ ۲۰۲۶/۱۱/۱۷؛ دامنه فقط تصمیم مهندسی D32 و A1. این سند مجوز عمومی‌شدن فایل یا اجرای B/C نیست.

## تصمیم‌ها و علت

- **Scanner واقعی: ClamAV 1.5.4-1**، بسته رسمی Linux x86_64؛ فراخوانی `INSTREAM` با socket استاندارد Python، بدون SDK دیگر. هر chunk طول ۴بایتی big-endian دارد و انتها chunk صفر است؛ فقط پاسخ دقیق `stream: OK` نتیجه پاک است. `FOUND` قرنطینه و خطای transport/timeout/ERROR حالت pending/retry است. TCP خود ClamAV احراز هویت ندارد؛ اسکنر فقط شبکه داخلی invest و بدون published port می‌ماند. [پروتکل رسمی](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)
- **قفل ابزار**: SHA256 بسته `28d6efc5b4423e7830c3559339552eb53870a9eac51ac4efb37d60530d329886`؛ امضای GPG جدا با کلید رسمی Talos از مستندات ClamAV بررسی شد: fingerprint `5BAD CA26 65EF 59DC F8A2 3D8B 707F 0DB4 8083 6771`، نتیجه Good signature. اعتماد هویتی کلید از HTTPS منبع رسمی است؛ keyring خصوصی پروژه تغییری در keyring میزبان نمی‌دهد. [روش رسمی تأیید](https://docs.clamav.net/manual/Installing.html)، [بسته](https://www.clamav.net/downloads/production/clamav-1.5.4.linux.x86_64.deb)، [کلید](https://raw.githubusercontent.com/Cisco-Talos/clamav-documentation/main/src/manual/cisco-talos.gpg)
- **ساخت قابل اجرا**: Docker Hub و ghcr در این محیط403 دادند و image اسکنر cache نبود. بسته رسمی دانلود/استخراج شد؛ باینری و shared libraries و پوشه certs روی همان Python3.14.10 slim-bookworm قفل‌شده پروژه کپی و `ldconfig` اجرا شد؛ نیازی به apt یا نصب میزبان نیست. فایل‌ها و build آزمایشی فقط `.tools/s05-a1/research/` هستند. ابزارهای سالم موجود پروژه دوباره نصب نشدند. image پژوهش `invest-clamav-research:1.5.4` با ID `sha256:4c24e4f4a7afba3897a5158164d2cac48bdb2a09c5a57d0280fc26ef7c4d58cf` اجرا شد؛ image تحویل و فرمان بازتولید نهایی در manifest تحویل ثبت می‌شوند.
- **امضاها قابل به‌روزرسانی، ابزار ثابت**: فایل CVD رسمی از `database.clamav.net` در volume اختصاصی اسکنر؛ `sigtool --info` اعتبار CVD را تأیید می‌کند. نسخه ابزار جای تازگی signature نیست؛ در این اجرای مصنوعی `daily.cvd` نسخه28186،355871امضا، زمان ساخت17Nov2026 06:30UTC و SHA256 `b7bc0dd0739b51440312cac5871766f1f6eb6abf44007c960662c28db5160649` تأیید شد. دریافت مستقیم با User-Agent استاندارد ClamAV کار کرد؛ `main.cvd` نیز کامل دانلود و با sigtool تأیید شد: نسخه63،3,287,027امضا، SHA256 `0b2182d229f46981ec8f535382222f7c9dfdd656b250ad47988b910a8d302365`. برای بهره‌برداری واقعی monitoring تازگی و FreshClam لازم است؛ استفاده از امضای ساختگی EICAR به جای signature محصول پذیرفته نیست. [نصب و RAM رسمی](https://docs.clamav.net/manual/Installing/Docker.html)
- **محدودیت scanner**: container با4GiB RAM،1CPU،64PID، readonly و tmpfs256MiB؛ nonroot10001. `MaxThreads2 / MaxQueue4 / StreamMaxLength20M / MaxFileSize20M / MaxScanSize80M / MaxRecursion8 / MaxFiles100 / MaxScanTime10000 / AlertExceedsMax yes / ConcurrentDatabaseReload no`. نتیجه عبور از محدودیت پاک محسوب نمی‌شود. timeout کلاینت30ثانیه؛ صف/آفلاین مانع ذخیره متن draft نیست. نیاز4GiB ناشی از حافظه engine و reload امضا طبق مستندات رسمی است، نه اندازه فایل ورودی.
- **تصویر: Pillow13.0.0** در uv.lock. فقط JPEG/PNG/WebP طبق نقش فایل، حداکثر25میلیون پیکسل؛ DecompressionBombWarning خطا، `n_frames=1` و load کامل الزامی. خروجی از pixelهای decodeشده به RGB/RGBA تازه بازرمزگذاری و EXIF/XMP/ICC/comment منتقل نشود؛ دانلود تصویر فقط مشتق امن. نوع واقعی از decoder و allowlist فرمت می‌آید، نه MIME کلاینت. [نسخه و سیاست انتشار](https://pillow.readthedocs.io/en/stable/releasenotes/)، [Image و بمب تصویر](https://pillow.readthedocs.io/en/stable/reference/Image.html)، [حفظ metadata و حذف صریح](https://pillow.readthedocs.io/en/stable/handbook/security.html)
- **PDF: pypdf7.1.0** در uv.lock؛ parser با `strict=True`، رد هر encrypted PDF حتی رمز خالی، بازرسی objectهای parseشده برای action/JavaScript/Launch/OpenAction/AA/embedded files/XFA و سایر محتوای فعال. جست‌وجوی bytes خام کافی نیست؛ نام/شیء فشرده باید پس از parse دیده شود. سقف object/depth و Configuration محدود؛ CPU20ثانیه،wall30ثانیه،RAM512MiB و محدودیت خروجی در subprocess مستقل. parser PDF هیچ JS یا attachment را اجرا/استخراج نمی‌کند؛ خطا یا مصرف بیش از سقف رد می‌شود. محدودیت‌های تجزیه تضمین بی‌خطر بودن مطلق PDF نیستند؛ اسکن مستقل نیز لازم است. [نسخه7.1.0](https://pypi.org/project/pypdf/7.1.0/)، [strict](https://pypdf.readthedocs.io/en/latest/user/robustness.html)، [Configuration7.1](https://pypdf.readthedocs.io/en/latest/modules/configuration.html)، [PdfReader](https://pypdf.readthedocs.io/en/latest/modules/PdfReader.html)
- **Worker/scheduler**: management command همان image Django، حلقه5ثانیه‌ای و purge هر60ثانیه با حالت `--once`؛ صف مدل PostgreSQL و `select_for_update(skip_locked)` از اجرای هم‌زمان و تکرار ایمن پشتیبانی می‌کند. parser process با resource limits داخل خودش و timeout والد اجرا می‌شود؛ از `preexec_fn` در worker چندریسمانی استفاده نشود. Celery/Redis تازه برای این کار یکپارچه کوچک لازم نیست. [قفل Django](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#select-for-update)، [resource](https://docs.python.org/3.14/library/resource.html)، [subprocess timeout](https://docs.python.org/3.14/library/subprocess.html)

## شاهد پژوهش واقعی

کانتینر خصوصی `invest-clamav-research` روی شبکه `invest_default`؛ بدون port میزبان و بدون دسترسی به داده برنامه/سرویس‌های دیگر. با CVD رسمی تأییدشده، INSTREAM برای متن مصنوعی سالم `stream: OK` و برای fixture امن استاندارد EICAR، `stream: Eicar-Test-Signature FOUND` داد. EICAR بدافزار واقعی نیست و فقط در فضای آزمون مصنوعی استفاده شد؛ هیچ fixture خطرناک واقعی دریافت/اجرا نشد. [ماهیت و هدف رسمی EICAR](https://www.eicar.org/download-anti-malware-testfile/)

این دو probe شاهد اتصال واقعی engine هستند؛ جای آزمون کامل API، قطعی/retry، جایگزینی و سهمیه A1 را نمی‌گیرند. آن‌ها باید روی نسخه نهایی و DB آزمون ایزوله اجرا شوند. گزارش و manifest مأموریت نتیجه نهایی را تعیین می‌کنند.

## گزینه‌های بررسی‌شده

ClamAV official Docker image با pin digest مطلوب بود ولی pull/inspect403؛ نصب apt نسخه متغیر و وابستگی اضافه می‌آورد؛ بسته رسمی hash/GPGشده راه قابل اجرا شد. Poppler26.01.0 میزبان موجود است ولی وابسته‌کردن runtime container به ابزار میزبان بازتولیدپذیر نیست. Pillow/pypdf قبلاً در image پروژه نصب نبودند؛ این دو وابستگی جدید برای قابلیت خواسته‌شده لازم‌اند و باید در lock افزوده شوند. پاسخ ثابت clean، regex تنها برای PDF و scanner فقط با custom EICAR signature رد شدند.

## مرز انتقال فرانت
آزمون واقعی۲۰MiB روی image، قطع بدنه در سقف پیش‌فرض۱۰MiB Next.js را آشکار کرد. گزینه experimental.proxyClientMaxBodySize در types/config-schema نسخه نصب‌شده16.4.6 تأیید و روی۲۱MiB قفل شد؛ بک‌اند همچنان۲۰MiB مدرک/۱۰MiB تصویر و رزرو اتمیک را اعمال می‌کند. [قرارداد رسمی گزینه](https://nextjs.org/docs/app/api-reference/config/next-config-js/proxyClientMaxBodySize)؛ صفحه رسمی هنگام بازخوانی در این محیط404 بود، وجود گزینه در package قفل‌شده نیز مستقیم بررسی شد. build سوم فقط فرانت و بازاجرای هدفمند ناشی از این شکست تازه است.
